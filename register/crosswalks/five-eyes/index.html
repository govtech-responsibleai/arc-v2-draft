Crosswalk: Five Eyes guidance on agentic AI

ARC maps its controls to ASD's ACSC, CISA, NSA, Cyber Centre, NCSC-NZ and NCSC-UK – Careful adoption of agentic AI services (May 2026 (published 1 May 2026)). Each mapping points to the nearest corresponding entry; it is not a claim that the two are the same.

Read it from either side: below, each item in that framework lists the ARC entries that map to it, and each ARC entry's own page lists its crosswalks.

DS1 · Designing secure agents – Controlled context

Section titled “DS1 · Designing secure agents – Controlled context”

Controls

  • CTRL-0016 (Level 0): Define clearly the agent's role, scope, and non-goals in the system prompt
  • CTRL-0019 (Level 0): Keep untrusted inputs out of system instructions, and enclose any untrusted content given to the model in delimiters marked as data
  • CTRL-0048 (Level 2): Implement methods to reduce hallucination rates in agent outputs
  • CTRL-0063 (Level 1): Prioritise search results from verified, high-quality domains
  • CTRL-0100 (Level 0): Load instruction, settings, and tool-configuration files only from locations the operator controls, and ask before using any that arrive with a workspace
  • CTRL-0106 (Level 1): Minimise the personal data an agent sends through its tools, and set a retention period for what it keeps

DS2 · Designing secure agents – Oversight mechanisms

Section titled “DS2 · Designing secure agents – Oversight mechanisms”

Controls

  • CTRL-0035 (Level 2): Require agents to decompose user goals into explicit sub-goals and validate necessity before proceeding
  • CTRL-0037 (Level 1): Require planning agents to include explicit safety constraints in all generated plans before execution
  • CTRL-0042 (Level 1): Require explicit human confirmation before executing high-impact or irreversible tool actions
  • CTRL-0053 (Level 0): Require human approval for communications on sensitive matters
  • CTRL-0056 (Level 0): Require explicit human confirmation before committing any business transaction outside limits that an accountable human has pre-authorised
  • CTRL-0065 (Level 0): Ensure every agent can be immediately paused or terminated by its operators
  • CTRL-0066 (Level 0): Ensure "take over" mode is activated when entering sensitive data
  • CTRL-0076 (Level 0): Require human approval for destructive changes to databases, tables, or files that cannot be readily undone
  • CTRL-0077 (Level 0): Enable versioning or soft-delete for managed object stores to allow recovery from accidental modifications
  • CTRL-0101 (Level 0): Give agents no write access to their own instructions, configuration, permissions, logs, or monitors

DS3 · Designing secure agents – Identity management

Section titled “DS3 · Designing secure agents – Identity management”

Controls

  • CTRL-0009 (Level 0): Use only tool servers and APIs, including MCP servers, that implement robust authentication mechanisms in production environments
  • CTRL-0011 (Level 0): Limit token scopes to the minimum privileges required and avoid broad or wildcard scopes
  • CTRL-0025 (Level 1): Ensure all inter-agent communications are encrypted in transit and prohibit plaintext channels
  • CTRL-0026 (Level 1): Require all agents to authenticate with verifiable, cryptographically signed identities before processing requests
  • CTRL-0029 (Level 0): Grant agents only the minimum permissions required for their designated tasks
  • CTRL-0030 (Level 1): Assign each agent a unique, verifiable identity with no shared credentials
  • CTRL-0039 (Level 1): Ensure each agent publishes standardised, machine-readable capability descriptors accessible to other agents
  • CTRL-0075 (Level 1): Do not grant write access to agents unless strictly necessary
  • CTRL-0082 (Level 2): Do not grant agents access to personally identifiable or sensitive data unless strictly required
  • CTRL-0095 (Level 1): Apply due diligence and technical bounds to third-party agents before delegating to them or transacting with them
  • CTRL-0102 (Level 1): Issue agents short-lived, task-scoped credentials, keep an inventory of them, and revoke them when an agent or integration is retired
  • CTRL-0104 (Level 1): Authorise each action against the principal it is done for, at the agent that carries it out

DS4 · Designing secure agents – Defence in depth

Section titled “DS4 · Designing secure agents – Defence in depth”

Controls

  • CTRL-0015 (Level 1): Treat all tool metadata and outputs as untrusted input requiring validation
  • CTRL-0020 (Level 2): Use a dedicated LLM to extract required fields from inputs and filter out extraneous text or embedded instructions
  • CTRL-0024 (Level 0): Define formal schemas for inter-agent messages and validate all messages against these schemas before processing
  • CTRL-0058 (Level 0): Restrict agents to proposing transactions whilst using a separate transaction controller for execution
  • CTRL-0090 (Level 1): Enforce data-flow and capability policies at runtime with a deterministic policy layer that separates untrusted content from privileged actions
  • CTRL-0097 (Level 0): Do not give one agent untrusted content, access to sensitive data, and an unrestricted outbound channel at once; remove one, or gate the outbound channel outside the agent

DV2 · Developing secure agents – Appropriate evaluation

Section titled “DV2 · Developing secure agents – Appropriate evaluation”

Controls

  • CTRL-0005 (Level 1): Conduct structured evaluation of multiple LLMs for instruction-following, performance, and safety before deployment
  • CTRL-0036 (Level 1): Regularly evaluate and test planning behaviour under representative workloads and failure scenarios
  • CTRL-0038 (Level 0): Conduct safety verification with domain-relevant stress tests and adversarial scenarios before deployment and on a regular cadence afterwards
